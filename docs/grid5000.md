# Grid'5000

The study can also run on [Grid'5000](https://www.grid5000.fr), on the production queue `abaca`. The local
path (`scripts/run_experiment.sh`, on one CUDA GPU) is unchanged. Both run the same code and publish to the
same model repository.

## How it runs

- **Compute on abaca.** Each site's frontend builds the environment and the study data once, in a CPU job.
  Each arm then trains as a chain of one-GPU jobs on one cluster.
- **Results on Hugging Face, once.** During training, checkpoints stay on the site's disk, and each link resumes
  from there. When an arm finishes, its checkpoint, weights, config and metrics are uploaded to `runs/<arm>/` in
  one commit, then deleted from the site. A chain must stay on one site, since its checkpoint lives there.
- **One chain per arm.** Each job queues its successor when it starts (`oarsub -a`), so the next job begins as
  soon as the current one ends, for any reason.
- **A chain stops when it stops moving.** If three jobs in a row end without a new metric record, the chain
  stops instead of resubmitting itself.
- **Your laptop** only pushes the code and sends commands through the frontend. It keeps no data and no runs.

What stays on the site, outside the repository: the packed environment, the study data (about 7 GB, rebuilt
from FineWeb-Edu if removed), the checkpoint of each arm while it trains, the metrics file of each arm, and chain state and logs in `~/gpt2-g5k/`.

## One-time setup, per site

1. On the frontend, create `~/.hf_token` with a Hugging Face token that can write to the model repository and
   the dashboard, then `chmod 600 ~/.hf_token`.
2. On the frontend, install uv once: `curl -LsSf https://astral.sh/uv/install.sh | sh`.
3. Check that the site has Python 3.12 (the scripts use the system Python only): `python3 --version`.

## Run

From the repository root on your laptop, copy the code to the site:

```bash
G5K_LOGIN=<login> bash scripts/g5k/transfer.sh <site>
```

Log in to the frontend, then, from the repository copy there:

```bash
ssh -J <login>@access.grid5000.fr <login>@<site>.grid5000.fr
cd ~/gpt2-fineweb-edu-curriculum-learning
python3 scripts/g5k/clusters.py --site <site>           # usable clusters and their free nodes
SEED=43 bash scripts/g5k/launch.sh <cluster> shuffle ascending  # one or two arms per cluster
python3 -m scripts.g5k.status                           # progress; wrap in `watch -n 60` to follow it
```

`launch.sh` first queues a CPU job that builds the environment and the data, if they do not match the code.
The arm jobs wait for it. Each arm's job asks for one GPU and 24 hours (`WALLTIME=H:MM` overrides it). Use the
same `WALLTIME` for all arms, since each link queues the next one with the same value.

Finished arms appear in the model repository under `runs/seed<N>/<arm>/`. `scripts.report` reads local runs, so the
figures need the metrics downloaded from the Hub first. That step is not automated.

## Stopping an arm

A running job queues its successor, so deleting only the running job lets the chain continue. Delete the
waiting successor first, then the running job:

```bash
oarstat -u                 # names look like gpt2-<arm>-seed<N>-<cluster>; the waiting one is in state Waiting
oardel <waiting-id>
oardel <running-id>
```

## Notes

- **Code changes.** Each job runs the code in the repository copy on the site when it starts. Push only when no
  chain is running. A change to the code the data and environment depend on (see `scripts/g5k/common.sh`,
  `fingerprint`) makes the next `launch.sh` rebuild the data, which takes a while.
- **Upload volume.** About 0.7 GB per arm, once, at the end.
- **Scratch.** Each job unpacks the environment and copies its arm's shard to `/tmp`, or `/dev/shm` when `/tmp`
  is small, and removes them on exit.
- **Trackio.** Workers publish the dashboard every 50 steps, as on the laptop.
